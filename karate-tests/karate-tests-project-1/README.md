# API Testing Project — Postman, Newman & Karate

This project is part of my QA automation portfolio.
It demonstrates how to test a simple public API (JSONPlaceholder) using three different tools:

Postman for manual and automated request validation

Newman to run the Postman collection from the command line

Karate for BDD-style API automation in Java

The goal was to cover the same API in multiple ways to show a complete understanding of manual testing, automated testing, and CI-friendly execution.

## Postman

The Postman collection contains requests for:

* GET /posts
* GET /posts/{id}
* GET /users
* GET /comments
* POST /posts
* an error-case request (GET /posts/99999)

Each request includes tests written in Postman’s scripting interface.

An environment file stores variables such as:

baseUrl = https://jsonplaceholder.typicode.com
postId = 1

This allows the same collection to run in different environments without modification.

## Running tests with Newman

Newman executes the Postman collection through the command line.
This is useful for CI pipelines or running tests outside Postman UI.

Example command used in the project:
```
newman run postman/API_testing_JSONPlaceholder.postman_collection.json \
-e postman/JSONPlaceholder.postman_environment.json
```

This runs all requests and outputs a clear summary of passes and failures.

## Karate API tests (Java)

The project also includes automated tests using Karate, a lightweight API testing framework that uses Gherkin syntax and integrates with JUnit5.

How the Karate tests are organized:

* jsonplaceholder.feature contains the scenarios
* KarateTest.java is the JUnit runner
* karate-config.js defines global configuration like: 
config.baseUrl = 'https://jsonplaceholder.typicode.com';

**Running the Karate tests**

From the karate-tests-project-1 directory: 
```
mvn clean test
```
Karate automatically generates HTML reports: [docs/karate-reports/karate-summary.html](docs/karate-reports/karate-summary.html)

These include request/response logs, execution timeline, and detailed scenario results.

## Tools & Versions

* Java: 17
* Maven: Standard build for Karate
* Postman + Newman
* Karate version: 1.4.1

Java 17 is required because Karate relies on libraries that are not fully compatible with more recent JDKs.
